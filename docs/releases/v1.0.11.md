A fix release from new CI that installs LazyChad end to end on fresh
Debian, Kali, Fedora, Rocky Linux, Arch and Ubuntu systems on every change.

## Fixes

- **Treesitter parsers on rolling-release distros (Arch, Kali, ...).** Newer
  npm versions skip `tree-sitter-cli`'s install script, so the `tree-sitter`
  binary was never downloaded and every parser failed to build.
  `lazychad-deps` now checks that it actually runs and fetches the binary
  itself (checksum-verified) when npm skipped it.
- **Treesitter parsers on older distros (Ubuntu 22.04, Debian 12, Mint 21,
  RHEL/Rocky/Alma 9).** The prebuilt `tree-sitter` needs a newer glibc than
  these ship. `lazychad-deps` now builds it from source once (a few minutes)
  when the prebuilt binary can't run.
- **The right Neovim is used.** If an older distro `nvim` came first on your
  PATH, `lazychad-nvim` treated a good install as failed and `lchad` started
  the old Neovim. Both now use the `/usr/local/bin/nvim` that `lazychad-nvim`
  installs, and warn about the PATH order.
- `lchad --doctor` now checks that `tree-sitter` runs, not just that it exists.

If parsers failed for you on 1.0.10, upgrade and run `lazychad-deps` again.

## Also

- Releases can be made from the GitHub Actions page (no terminal needed).

Upgrading a `.deb`/`.rpm` from v1.0.9 or earlier? See the
[v1.0.10 notes](https://github.com/MistanKh/LazyChad/releases/tag/v1.0.10):
back up `~/.config/LazyChad` first.
